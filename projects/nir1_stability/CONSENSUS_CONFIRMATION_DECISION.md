# НИР-1: замороженное решение о проверке согласованности структур

**Предрегистрация до S2.** Изменять веса, пороги, список систем, наборы сидов или выбирать успешные случаи после просмотра S2 запрещено. Научный смысл — ответить, обобщается ли преимущество консенсуса полных независимых запусков EPDE с уже просмотренных S1/S1b систем.

## Мотивация

Для чистого исходного EPDE на S1b истинная структура появляется на фронте только в 17/25 запусков; последующий SparseFront не дал прироста. Замена регуляризатора на v1, v2 и v3 часто удаляла истинные слагаемые. В ретроспективном анализе **только уже сохранённых** 5-сидовых запусков обнаружено, что правильная структура KdV при 2/5 выбиралась дважды, тогда как ошибочные решения были неповторяющимися. Это post-hoc гипотеза, **не** доказательство улучшения.

## Замороженная новая процедура

Код: `projects/nir1_stability/nir1/consensus.py` в ветке `nir1`.

1. Выполнить K=5 *полноразмерных* исходных PIC/EPDE `default` запусков при фиксированном `data_seed=0` и `optimizer_seed=0,1,2,3,4`. Популяция 16 × пять эпох без урезания. Один физический объект и одно начальное условие на всю пятёрку.
2. Взять **один native PIC-selected** кандидат из каждого законченного поиска, по его `metrics.selected_index`. Истины, таблицы benchmark truth, данные другого объекта для выбора не читать.
3. Привести выбранные уравнения к каноническим множествам токенов, инвариантным к масштабу и переносам членов относительно знака `=`.
4. Если есть **единственная наиболее частая структура**, появившаяся не менее двух раз, принять её; при равной моде или полном отсутствии повторений принять native selected кандидата минимального `optimizer_seed` (seed 0).
5. Неполный, аварийный или неподдерживаемый поиск не отбрасывать. Группа из пяти неполна => научный вывод о консенсусе запрещён. Никаких выборочных повторов только неудачных алгоритмических запусков.
6. Истинную структуру использовать **только для финальной оффлайн-оценки**, после фиксации единственного выбранного уравнения.

## Независимые системы S2

Ранее не использованные ни для S1, ни для постфактум настройки консенсуса S1b/S1d:

- `ks` — Kuramoto–Sivashinsky;
- `pde_compound` — нелинейная диффузия;
- `pde_divide` — PDE с делением на координату;
- `ns` — Navier–Stokes.

Всего **4 системы × 5 независимых optimizer seeds = 20 полноразмерных EPDE запусков**, откуда будет только четыре консенсусных решения, а не двадцать. Это ограничение обусловлено размером существующего банка: `wave` уже использован в S1b и исключён из новой S2.

## Предписанные метрики и валидность

- Успех единственного консенсусного уравнения по точному структурному совпадению `canonical_tokens`, один бинарный ответ на систему.
- Исходный baseline: средняя доля успехов среди пяти native PIC выборов по той же системе (это K решений за K поисков, **не** равный бюджет одному консенсусному решению).
- Разность в п.п. считается как среднее по четырём независимым системам от `consensus_success - native_success_fraction`.
- Точный двусторонний sign-flip по четырём физическим системам, а не по 20 коррелированным сидами. Минимально возможный p-value при всех однонаправленных знаках **0,125**; поэтому дизайн не способен подтвердить `p<0.05`, даже при идеальном эффекте. Любой плюс будет **предварительным**.
- Показывать фактическое суммарное CPU-время пяти поисков и время одной native оценки; нельзя объявлять прирост без доплаты вычислениями.
- Отдельно оценить долю совпадающих структур, случаи равной моды, front truth coverage и ограничения по переобучению на S1.

**Критерий перспективности, не научная значимость:** разность `≥+10 п.п.`, отсутствие недоучтённых сбоев и улучшение хотя бы на двух из четырёх физических систем. Даже при этом потребуется более широкий новый S3 или новый банк независимых условий до публикации. При меньшем эффекте гипотеза отклоняется без настройки правил на этих четырёх системах.

## Инженерная безопасность

- Отдельный Actions workflow с immutable manifest, `record_sha256` и сохранением каждого шард-артефакта.
- Агрегатор S2 вызывает `consensus_report` **только после** сверки полного immutable списка, не выбрасывает таймауты или ошибки.
- Никакой записи в ITMO upstream, `main`, `pic/review-ready`; только `MakSoS1/EPDE:nir1`.
- Профилирование chi2 и точные E1 ускорения — **отдельная ветвь экспериментов** и не меняют ни одну из пяти исходных эволюций в S2.

**Эта запись — заморозка решения и кода анализа до просмотра данных S2; результаты S2 здесь намеренно отсутствуют.**
