# НИР-1 — трек улучшения точности v4: несколько фронтов EPDE

**Статус:** алгоритм и регрессионные тесты реализованы в `nir1`; S1b уже повторно проанализирован, исходный S1 повторно анализируется, S2 пока выполняется. Результатов независимого подтверждения v4 на новых данных нет.

## Научный вопрос

Предыдущие изменения регуляризации v1–v3 чаще исключали истинное уравнение до окончательного отбора. Попытка заменить окончательный Pareto-селектор SparseFront не улучшила S1b: baseline и SparseFront оба 17/25. Проблема — не только финальный селектор, а наличие и воспроизводимость правильных кандидатов в популяции.

Предложена иная гипотеза: ошибочно отклонённая модель может присутствовать **на нескольких фронтах разных полноразмерных поисков**, хотя индивидуальный PIC-селектор ни разу её не выбрал.

## Варианты, которые нельзя смешивать

- `PIC`: один полный поиск EPDE, одно выбранное уравнение; исходная точность считается по всем optimizer seeds.
- `consensus v1`: ровно K=5 полных поисков, затем голосование *только среди пяти итоговых* структур.
- `allfront consensus v2`: ровно те же K=5 поисков, объединение **всех** Pareto-кандидатов, число независимых рестартов с данной структурой — главный показатель. Дубликаты внутри одного фронта засчитываются только как один голос. При частотном равенстве дополнительно сравниваются native selected frequency, затем нормированная по фронту невязка; если ни одна структура не встречается хотя бы в двух рестартах, используется неизменённый алгоритм consensus v1.

Все решения принимаются *без чтения истины*: вычисляется каноническая структура из факторных токенов; целевая функция известна без эталонного уравнения. Истина используется только **после** выбора в отдельном анализаторе.

Код: `nir1/front_consensus.py`, `nir1/front_consensus_dev.py`, `nir1/front_consensus_report.py`. Тесты: `tests/test_front_consensus.py`. Автоматический анализ архивов: `nir1-front-replay.yml`, `nir1-s1-front-replay.yml`.

## Фактически полученное на S1b (исторически просмотренные пять систем)

[GitHub Actions, точный повторный анализ исходных 50 записей](https://github.com/MakSoS1/EPDE/actions/runs/38090954500). Сверен immutable манифест на 50 ID и исходные `record_sha256`; *новых эволюций нет*.

| Метод | Точные структуры |
|---|---:|
| PIC по отдельным рестартам | **17/25 = 68%** |
| Consensus v1 (пять поисков → одно решение на систему) | **4/5 = 80%** |
| Allfront consensus v2 (те же пять поисков) | **4/5 = 80%** |

Системы, где v1 и v2 были точны: `burgers_inviscid`, `kdv`, `kdv_cossin`, `wave`. Lorenz не восстановлен. Парное v2 минус v1 = **0 п.п.**, exact system-level sign-flip `p=1`. Таким образом новые голоса **не добавили качества** по сравнению с v1.

Рост 68%→80% нельзя объявлять независимой научно подтверждённой прибавкой качества: **это две разные единицы принятия решения и бюджет пять полных поисков на одно уравнение**, а исходные данные ранее уже анализировались. Результат полезен для решения, стоит ли развивать согласованный повторный поиск.

## Дополнительная проверка на S1 (исходные 120 записей)

[Независимо пересобранный аудит исторического S1, GitHub Actions #38091094636](https://github.com/MakSoS1/EPDE/actions/runs/38091094636), оригинальный код поиска `8d3aa947bc074000dee6d8acf96c4862eb74d81c`, immutable manifest `7993e0811e9cc9f14f7a3ff79aeab76d618b4144d8a002c9ae1b45cf413ce4e7`. Проверены все 120 исходных записей, для нового голосования использованы **только 30 baseline**. Новых эволюций не запускалось.

| Метод | Успех |
|---|---:|
| Штатный PIC, каждый из пяти сидов отдельно | **18/30 = 60%** |
| Согласование пяти native PIC-selected моделей, v1 | **5/6 = 83,3%** |
| Согласование всех фронтов, v2 | **5/6 = 83,3%** |

На `burgers`, `duffing`, `lv`, `ode`, `vdp` согласование обоих типов было правильным; на `ac` — неправильным. V2 vs V1 = **0 п.п.**, exact cluster p-value **1,0**. Средние проценты по 30 индивидуальным решениям и по шести пятикратным ансамблям имеют **разную стоимость и единицу анализа**: это разведочная относительная польза многократного поиска, а не увеличение точности одного EPDE при том же бюджете.

Итак, на двух ранее использованных наборах наблюдаем прирост от **голосования native selected**, а от включения *всех* фронтов дополнительного эффекта **не обнаружено**. Приоритет следующей проверки — предрегистрационный консенсус v1 в S2. **Нельзя** выдавать S1 / S1b за независимое подтверждение.

## Проверки, которые ещё нужны

- Анализ тех же правил на первоначальном S1 выполнен и приведён выше; он остаётся исключительно разработкой.
- Дождаться завершения замороженного S2 (4 независимые системы × 5 семян, [Actions #38087199947](https://github.com/MakSoS1/EPDE/actions/runs/38087199947)). V1 закреплён до запуска S2, тогда как v2 сформулирован **во время выполнения** S2 и является дополнительным разведочным анализом, не строгим заранее зарегистрированным подтверждением.
- Анализировать v2 на завершённом S2 только после сверки **каждого** manifest ID/ checksum. Использовать формулу точного структурного успеха из PIC только ПОСЛЕ заморозки выбранного уравнения.
- Для подтверждения v2 требуется ещё одна независимая S3 на **ранее не использованных условиях/системах**, не на S1, S1b, S1c, S1d и не на уже просмотренном S2. Порог существенного улучшения: не менее +10 процентных пунктов при честном учёте 5× вычислений, с нужным числом независимых физических систем.
- Нельзя автоматически увеличивать популяцию/эпохи в одном варианте и сравнивать его с меньшим бюджетом исходного EPDE: результаты будут несопоставимы.

**Принятое инженерное решение:** трек оптимизации E1 зафиксирован отдельно в `E1_FREEZE_2026-10-11_RU.md`, без новых экспериментов по ускорению до решения задачи точности.
