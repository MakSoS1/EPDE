# НИР-1: предрегистрация дополнительного аналитического transfer-бенчмарка S2e

**Версия:** 11 октября 2026 г. **Статус:** НАБОР И ПРОТОКОЛ ЗАФИКСИРОВАНЫ, полноразмерные научные прогоны не запущены; перед запуском обязателен зелёный интеграционный smoke всех десяти задач.

## Зачем он нужен

На двух *уже просмотренных* наборах S1/S1b простое согласование пяти полноразмерных EPDE запусков (v1) имело описательное улучшение над усреднённым одиночным baseline:
- S1: 18/30=60% для отдельных поисков против 5/6=83,3% для пяти-поискового консенсуса;
- S1b: 17/25=68% против 4/5=80%.

Это **не равнобюджетное** сравнение (консенсус использует K=5× полный поиск) и не независимое подтверждение. Более сложная all-front v2 на обоих наборах дала те же 5/6 и 4/5, поэтому дальнейшая настройка v2 не допускается.

Чтобы избежать псевдоповторов старого PIC, добавлены десять **аналитически проверяемых** уравнений, никогда не использованных в S1/S1b:
- ODE: `nir1_decay`, `nir1_logistic`, `nir1_quadratic`, `nir1_cubic`, `nir1_harmonic`;
- PDE: `nir1_advection`, `nir1_heat`, `nir1_reactiondiff`, `nir1_wave`, `nir1_advdiff`.

Решения заданы **до EPDE**, по явным математическим формулам; проверяются независимыми тестами численного остатка PDE/ODE, без обучения или подбора на истине. Каждый PDE генерируется как сумма нескольких волн или мод, чтобы избежать хотя бы тривиальной пропорциональности `u` и `u_xx` для одной моды. Исходные данные не скачиваются, детерминированы из формул.

### Важное ограничение независимости

Десять тестовых **систем** нельзя автоматически считать десятью независимыми законами природы из всей популяции PDE: набор содержит пять ODE и пять PDE; экспоненциальный спад, логистическое и кубическое насыщение родственны по численной геометрии, тепло и реакция-диффузия имеют общие операторы. Поэтому выводы по n=10 сопровождаются чувствительностью к группировке по типу ODE/PDE, разбивкой на физические семейства и широкой неопределённостью. Они не заменяют проверку на полевых данных и сложных независимых нелинейных PDE.

## Жёсткий барьер перед запуском

1. `test_analytic_transfer.py` — все 20 проверки формы и независимого дифференциального остатка прошли.
2. GitHub Actions `nir1-transfer-smoke.yml` выполняет smoke-версию настоящего EPDE для всех десяти систем (`--smoke`, 4 особи×1 эпоха, **не научный результат**). Каждая матричная job должна завершиться success.
3. Заморозить конкретный Git SHA, манифест с ровно **10×5=50 run IDs**, `manifest_sha`, seed-список и бюджет.
4. Не запускать полные S2e исследования, если хотя бы один loader, дифференцирование или EPDE-search smoke оказался несовместим.
5. В случае неисправности одной системы исправление документируется и набор либо полностью перезапускается с новой заморозкой, либо вся замороженная серия получает статус неполной; запрещено выкидывать из списка только неудобную систему.

## Предписанное исполнение

- На каждую систему пять **реальных** независимых поисков `default`, `optimizer_seed=0..4`, `data_seed=0`, `noise=0`.
- У всех стандартный PIC budget **16 особей × пять эпох**; никакой оптимизации E1/новой регуляризации/SparseFront. Замороженный benchmark [S2e предложенный YAML](manifests/s2e-transfer-proposed.yaml) не запускает Actions до интеграционной проверки.
- Для каждого 5-run набора собрать ровно **одно** уравнение `consensus_decision` v1, ранее замороженным для основной S2.
- Отдельные истины использовать **только после** выбора уравнения.
- Вторичная абляция: `pool_consensus_decision` v2 на тех же 5 фронтах, **без новых эволюций**.
- **Равнобюджетный контроль:** `min_discrepancy_restart` из тех же 5 запусков выбирает единственный *native PIC selected* закон с минимальной невязкой; оба метода платят K=5 полных поисков за одну окончательную структуру. Случай seed0 тоже публикуется только как отдельный дешёвый baseline, не заменяя равнобюджетный.
- Время суммарного CPU всех пяти поисков, оценка online vs offline и количество найденных фронтов обязательны.
- Алгоритмические `crash/timeout` = неуспех, инфраструктурное `incomplete` блокирует научную сводку, а не исключается из знаменателя.

## Метрики, вывод и ограничения

- Первичная: **доля выбранных точных структур по 10 системам для v1 консенсуса**; сравнение v1 против равнобюджетного min-discrepancy — основная парная абляция. Сравнение против среднего PIC из 50 runs — отдельное описательное, поскольку единицы отличаются.
- Вторичные: v2 vs v1 (ожидается 0 до независимой проверки), original native front_exact, стабильность/мода структуры, затраты пяти поисков и success_front по каждому system.
- Для десяти систем двусторонний exact system-level sign-flip имеет минимальный `2/2^10 = .001953125`, но **коррелированные физические семейства снижают реальную мощность**. Результаты приводятся по ODE/PDE отдельно, с групповым bootstrap и чувствительностью по физическим семействам. Не считать 50 optimizer seeds независимыми.
- Содержательная цель: **≥10 процентных пунктов** выигрыша v1 против равнобюджетного конкурентного селектора *и* отсутствие потери на обоих типах ODE/PDE, подтверждение на независимом PDE корпусе до статьи.
- Если v1 не улучшает равнобюджетный baseline, публикация отрицательного результата обязательна; выбирать другой порог по этим десяти тестам запрещено.
