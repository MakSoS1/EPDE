# Multisample в EPDE: аудит, реализация и эксперименты

Дата: 13 ноября 2026 года. База: `domain_refactor`, коммит `8690035e90b234b34ed5a2fb0bb8e4a814dcbdf7`. Реализация подготовлена в отдельной ветке `research/multisample-2026-11-13`.

## 1. Результат работы

Добавлен явный режим поиска общего уравнения по независимым записям: `multisample_mode='joint'`. В режимах `plain` и `assignment` он оценивает один вектор физических коэффициентов по всем выборкам, проверяет ранг общей матрицы и использует этот же вектор при оценке кандидата и окончательного уравнения. По умолчанию сохраняется прежний режим `mean`.

Исправлены ошибки независимой подготовки выборок, общих многомерных областей, порядка строк при ненулевой временной оси, повторного сглаживания, кэширования и определения постоянных токенов. Устаревший `EpdeMultisample` заменён адаптером современного `EpdeSearch`; отдельная копия оптимизатора ему больше не нужна.

Проведены 98 вычислительных экспериментов: 32 с заданными членами уравнения, 60 запусков полного эволюционного поиска и 6 проверок совместимости. Итоговые статусы: **97 `ok`, 1 ожидаемый `no_candidate`, 0 ошибок выполнения, 0 таймаутов**. Статус `ok` означает, что процедура вернула модель; он не означает правильного восстановления закона.

Главное подтверждённое преимущество: на уравнении реакции–диффузии, для которого отдельные записи имеют вырожденную матрицу признаков, совместный полный поиск восстановил правильную структуру в **5/5** запусков, прежний режим — в **0/5**. На шумных данных преимущество в предсказании не всегда сопровождается правильной структурой. Все неудачные структуры и лишние члены сохранены в результатах.

## 3. Почему среднее коэффициентов недостаточно

Пусть для записи `s` вычислены признаки `X_s`, целевая производная `y_s` и неотрицательные веса строк `g_s`. Исторический путь сначала решает отдельные регрессии, затем усредняет коэффициенты:

\[
\hat\beta_{mean}=\frac{1}{S}\sum_{s=1}^{S}\hat\beta_s.
\]

В общем случае это не решение общей задачи на всех записях. Если отдельные матрицы имеют недостаточный ранг, некоторые коэффициенты вообще нельзя определить по каждой записи независимо. Усреднение локальных решений не восстанавливает утраченную информацию.

В новом режиме решается задача

\[
\hat\beta=\arg\min_\beta\sum_{s=1}^{S}\sum_i w_{si}(y_{si}-X_{si}\beta)^2.
\]

Политика `samples` задаёт `w_si = g_si / sum_i(g_si)`: каждая запись получает одинаковую суммарную массу. Политика `points` оставляет `w_si = g_si`: более плотная или длинная запись может получить больший суммарный вес. Свободный член, когда он входит в выбранную структуру, также общий.

Признаки и целевая производная не нормируются отдельно по каждой записи. Это сохранило бы форму сигнала, но изменило физический смысл общего коэффициента. Для численной устойчивости столбцы уже объединённой взвешенной матрицы уравновешиваются, задача решается через SVD, а коэффициенты переводятся обратно в физический масштаб. Ранг проверяется для объединённого взвешенного набора с действующим допуском линейной зависимости.

**Граница этой реализации:** политика весов относится к оценке коэффициентов и предварительному отбору предложений. Она не переопределяет существующие WAPE, L2, относительный L2 и оценку cancellation. Минимум WLS не объявляется минимумом WAPE. Согласованность таблицы кандидатов и готового уравнения отдельно проверена для всех четырёх метрик.

### Пример совместной идентифицируемости

Истинное уравнение:

\[
u_t=-0.2u+0.1u_{xx}.
\]

Обучающие записи имеют вид

\[
u_s(x,t)=A_s\exp[(-0.2-0.1k_s^2)(t-t_{0,s})]\sin(k_sx),\qquad k_1=1,\;k_2=2.
\]

На каждой записи `u_xx = -k_s² u`, поэтому матрица `[u, u_xx]` имеет ранг один. Вместе записи дают ранг два. Правильный объект проверки — общая матрица; проверка только первой записи ошибочно отвергает эту структуру и делает результат зависимым от порядка опытов.

Отложенное поле использует новую сетку и смесь пространственных мод, не встречавшуюся при обучении. Поэтому проверяется перенос закона, а не только воспроизведение тех же двух пропорциональных столбцов.

## 4. Исправленные ошибки и регрессии

| Область | Ошибка | Новое поведение и проверка |
|---|---|---|
| Общая 2-D область | Сравнение исходной формы с плоскими значениями кэша могло завершаться неоднозначным булевым сравнением | Две записи используют одну область; проверены обычные строки и evaluation stride |
| Временная ось | Перестановка оси после уплощения приводила к ошибке или несогласованному порядку строк | Данные, производные и маска сохраняют один порядок C; проверен `time_axis=1` |
| Повторная подготовка | Сглаживание повторно применялось к уже сглаженному полю | Каждый rebuild начинает с копии исходного наблюдения; проверены force, изменение порядка производных и освобождение кэша |
| Частичные готовые производные | Наличие готовых производных одной переменной скрывало проверку границ для другой | Проверка схемы применяется к переменным, производные которых ещё нужно вычислить |
| Активный набор | Наличие токенов и геометрия зависели от неактивных областей и служебного subcache 0 | Проверки используют активные записи; добавлены ненулевые ID и лишняя ранее созданная область |
| Повторный cache ID | Поиск производной мог пользоваться старыми именами переменных | Индекс кодов производных ведётся по subcache и очищается при его замене |
| Пользовательский evaluator | Сохранялись старые координаты при повторном использовании sample ID | Вычисление использует переданные текущие сетки; поддержаны словари с ключами без 0 |
| Входные данные | Пустые наборы, разные переменные, повторные ID и нечисловые/нефинитные поля могли проходить слишком далеко | Ранняя проверка с контекстом записи; порядок переменных согласован между опытами |
| Конфликт Domain ID | Новый набор координат мог использовать прежний кэш области | Разные координаты под одним ID отвергаются до подмены области |
| Постоянные токены | Разные между опытами константы удалялись; результат зависел от ID | Постоянство проверяется по всем активным значениям вместе |
| Жизненный цикл токенов | Одна выборка навсегда удаляла токен из переданного семейства и кэша | Фильтруется копия списка токенов пула; исходное объявление и данные сохраняются для последующих fit |
| Joint assignment и LASSO | Финальный legacy-refit отменял балансировку выборок и менял коэффициенты после оценки кандидата | Конфигурация с непредусмотренным физическим масштабом коэффициентов отвергается явно |
| Fill-and-prune | Предложения отключались для нескольких записей | В joint-режиме Gram строится из независимых блоков с теми же весами; проверены strong/weak и обе политики весов |

Характерный случай постоянного параметра: две записи удовлетворяют `u_t = p - u`, но в первой `p=1`, во второй `p=2`. Токен `p` постоянен внутри каждого опыта, однако необходим общему уравнению. Регрессионные проверки покрывают ID `(0,1)` и `(7,19)`, обратный порядок записей и последовательность «одна → две → одна». Нефинитный кэшированный столбец не исчезает под видом постоянного: кандидат должен быть отвергнут соответствующим численным контролем.

## 5. Экспериментальный протокол

Полный код генерации данных, запуска и независимого оценивания находится в [benchmark.py](benchmark.py). Подробная схема результата и команды фильтрации — в [README.md](README.md).

Исследуются аффинное ОДУ, логистическое ОДУ, затухающая связанная система из двух ОДУ и PDE реакции–диффузии. Дополнительные отрицательные контроли проверяют противоречащие друг другу законы и изменение плотности сетки.

Этапы отделены друг от друга:

1. **Фиксированная структура:** правильные непостоянные члены известны, но оценивание и проверки выполняют настоящие операторы EPDE. Это тест реализации коэффициентов, а не открытие структуры.
2. **Assignment:** EPDE выбирает целевую часть и подмножество из переданного набора членов.
3. **Полный поиск:** вызывается `EpdeSearch.fit`, начальная популяция случайная, истинные уравнения в неё специально не вставляются.

Полный поиск использует seeds `0,1,2,3,4`, NSGA-II, запрошенную популяцию 8 и 4 эпохи. Внутренние правила разнообразия EPDE могут расширять популяцию. Жёсткие лимиты — 90 секунд на полный поиск и 45 секунд на остальные задания, включая импорт worker. Одновременно работают не более трёх отдельных процессов; вычисления CPU выполняются с одним потоком на процесс. Конфигурация и кэши EPDE глобальны для процесса, поэтому несколько поисков не смешиваются в одном интерпретаторе.

Для чистых данных передаются аналитические производные. В noisy FD производные вычисляет сам EPDE отдельно на каждой зашумлённой записи. Уровень `0.01` означает стандартное отклонение независимого гауссовского шума, равное `0.01 * std(clean field)`; это не процентная погрешность производной. Фиксированные структуры также проверены при 5% шума.

Отложены целые чистые траектории или поля с новыми начальными условиями. Они не поступают в обучающий пул. Среди возвращённых моделей выбирается модель с минимальной средней обучающей fitness; ни истинные коэффициенты, ни ошибка на holdout не используются для выбора. Все возвращённые модели сохраняются.

Структура считается совпавшей по активным каноническим коэффициентам с заранее фиксированным порогом `1e-8 * max(1, max(abs(coefficients)))`. Ошибка коэффициентов учитывает лишние члены. Для системы приводится максимум ошибки по её уравнениям; в таблице ниже — медиана по пяти запускам. Holdout residual — относительная L2-норма невязки на чистых отложенных данных, нормированная целевой производной.

На чистой PDE измерено исправление математического недостатка прежнего подхода. На чистых ОДУ оба режима уже восстанавливают закон с точностью округления; сравнение последних знаков таких чисел не доказывает практического превосходства.

На шумном логистическом ОДУ joint сохраняет небольшой лишний свободный член во всех пяти запусках. Поэтому строгая структура хуже, хотя holdout-невязка уменьшается примерно в 5.4 раза, а относительная ошибка интегрированной отложенной траектории — с `0.00171` до `0.000336`, примерно в 5.1 раза. Ошибка коэффициентов при этом выше. Это конкретный компромисс между структурой и предсказанием, а не универсальная победа одного режима.

На шумной связанной системе и PDE ни один режим не достигает строгой правильной структуры при этом бюджете. Joint уменьшает численные ошибки, но это не основание объявлять задачу символического открытия решённой.

### Контроли и совместимость

- **Плотность сетки:** четырёхкратное увеличение числа точек второй противоречащей записи оставляет коэффициент `-2.5` при `samples`. При `points` он закономерно меняется с `-2.5` на `-3.4`. Оба результата совпали с независимо рассчитанными ожиданиями.
- **Несовместимые законы:** записи с коэффициентами `-0.4` и `-1.0` не дают нулевую общую невязку. Плохая запись не выбрасывается ради искусственного успеха.
- **Слабые строки, заданные члены:** совместный fit восстанавливает логистическое ОДУ с относительной ошибкой коэффициентов `4.31e-14`, PDE — `7.73e-10`. В этих заданиях проверено фактическое использование weak-представления.
- **Assignment:** логистический пример восстановлен в обоих режимах. В одном проверенном задании PDE итоговый выбранный вариант не совпал с истиной даже в joint, с ошибкой коэффициентов около `0.989`. Регрессии доказывают, что общий правильный вектор доступен и согласован с его оценкой; они не доказывают, что вся политика выбора цели и варианта всегда его предпочитает.

## 7. Границы выводов и оставшиеся вопросы

Совместный режим поддержан для `plain` и `assignment` в solver-free multiobjective-поиске со второй целью instability и физическими коэффициентами. Joint с `repair`/VWSR support selection явно отвергается: локальный sparse-fit может выкинуть нужные столбцы ещё до объединения. Простая замена финального среднего на общую регрессию это не исправляет. Обычный VWSR в режиме `mean` сохраняет прежний путь.

Instability остаётся существующей диагностикой по независимым сеткам каждого опыта. Она не заменяется нулём для локально вырожденной матрицы и не интерпретируется как доказательство согласия коэффициентов между опытами. В частности, `het_raw` может сообщать неразрешённую локальную оценку при хорошем общем ранге. Общий ранг, невязка каждого опыта и перенос на отложенную запись отвечают на другие вопросы.

Если целевая производная тождественно нулевая в одной записи, действующие WAPE и amplification guard остаются проблемными: WAPE неопределён, а amplification получает бесконечность. Эта политика не менялась. Таким образом, равновесная траектория не гарантированно принимается даже при идентифицируемости на остальных записях.

Политика `samples` компенсирует число строк, но не оценивает зависимость между экспериментами. Дублированная запись не становится независимым свидетельством. Разные продолжительности, области пространства, шумы и неравномерность сетки также требуют осмысленной интерпретации весов; автоматическая квадратурная мера не добавлялась.

В FD-стресс-тесте PDE задан `boundary_width=2`, тогда как предупреждение действующего дифференциатора сообщает о более широком краевом шаблоне для второй пространственной производной. Часть сохранённых строк использует краевую обработку. Оба режима видят одинаковые строки; результаты являются проверкой именно этой зафиксированной конфигурации, а не оптимально настроенного дифференциатора. Чистый аналитический пример совместного ранга от этого не зависит.

Пять seeds и небольшой бюджет дают регрессионное свидетельство на перечисленных задачах. Не заявлены: полный PDE rollout, сравнение при одинаковом общем числе точек с одной траекторией, большой перебор настроек, шумовой benchmark слабой постановки или универсальная вероятность восстановления структуры. Фиксированные шумовые эксперименты используют seed 0.

## 8. Какие идеи следуют из измерений

**Приоритет 1 — выбирать структуру по целым отложенным опытам.** Небольшой лишний intercept на noisy logistic показывает, что минимум обучающей ошибки может предпочитать более сложную структуру. Следующий отдельный эксперимент — leave-one-trajectory-out с выбором более простой модели в пределах статистически сопоставимого качества. Делить соседние строки одной траектории случайным образом для этой цели недостаточно: так не проверяется перенос между опытами. Финальный тестовый опыт следует сохранить отдельно от выбора модели.

**Приоритет 2 — совместный sparse support selection.** Для полноценного joint VWSR нужно выбирать общую структуру из объединённой информации до локального отсечения членов. Возможная постановка — общий вектор коэффициентов и явный штраф на структуру при сохранении независимых групп строк. Потребуются случаи, где истинный член неидентифицируем в каждом опыте отдельно, но необходим совместно; положительный PDE-пример уже даёт основу для такой проверки.

**Приоритет 3 — различать общий закон и меняющиеся параметры.** Если опыты физически отличаются известным параметром, этот параметр можно передать как наблюдаемый токен: пример `u_t=p-u` теперь поддерживается корректно. Если параметр неизвестен, нужен отдельно сформулированный режим с общей структурой и частично различными коэффициентами. Подмена этой задачи жёстко общим коэффициентом закономерно оставляет невязку, как в отрицательном контроле.

**Приоритет 4 — исследовать оценивание производных отдельно от агрегирования.** Ошибка второй FD-производной на шумной PDE остаётся большой. Сравнение сильной и слабой постановок стоит проводить на одинаковых исходных наблюдениях, с одинаковыми seeds, открытыми окнами/границами и отдельным holdout. Эти данные не доказывают, что уже сделанное совместное оценивание само решает проблему шума.

Эти направления отделены от завершённых исправлений, поскольку каждое меняет статистическую или поисковую постановку и требует своего сравнения.

## 9. Использование

Два новых параметра доступны как аргументы `EpdeSearch`/`EpdeMultisample` и в группе `objectives` конфигурации:

```python
objectives = {
    "multisample_mode": "joint",
    "multisample_weighting": "samples",
}
```

Полный минимальный пример запуска с независимыми FD-производными:

```python
import numpy as np
import epde

np.random.seed(11)
records = []
for n, amplitude, origin in [(72, 1.0, 0.0), (96, 2.0, 10.0)]:
    t = np.linspace(origin, origin + 3.0, n)
    u = amplitude * np.exp(-0.4 * (t - origin))
    records.append((t, {"u": u}))

search = epde.EpdeMultisample(
    records,
    use_solver=False,
    device="cpu",
    engine="nsga2",
    system_rps_mode="plain",
    multisample_mode="joint",
    multisample_weighting="samples",
    discrepancy_metric="wape",
    instability_metric="dyad",
    default_preprocessor_type="FD",
    boundary_width=3,
    data_fun_pow=1,
    deriv_fun_pow=1,
    equation_terms_max_number=2,
    equation_factors_max_number=1,
    population_size=4,
    training_epochs=2,
    system_rps_params={"variable_order_seed": 11, "fill_probability": 0.0},
    verbose_params={"show_iter_idx": False},
)
try:
    search.fit(max_deriv_order=(1,))
    search.equations_by_variable()
finally:
    search.close()
```

Для разных препроцессоров или ширин границ лучше создавать отдельные `Domain` и `Trajectory`, затем вызывать обычный `EpdeSearch.fit` со списком траекторий. Аналитические производные передаются по отдельности через `createTrajectory(derivs=...)` или sample-major аргумент `EpdeMultisample.fit(derivs=...)`.

По умолчанию EPDE освобождает тензорный кэш после `fit`. Для последующей диагностики `equation.evaluate()` нужен `config={"runtime": {"free_tensor_cache_after_fit": False}}`; сохранённые текстовые уравнения и коэффициенты доступны и без удержания тензоров. Повторный `fit` после штатного освобождения проверен отдельным тестом, включая замену записей законом с другим коэффициентом.
