# Starting settings and explained comparisons

The user requested fast editable parameter suggestions, a clearer replacement
for “Preset”, and explained comparison of EPDE, PySINDy, DeepMoD and DISCOVER.

## Product behavior

New numerical inputs receive method-specific starting suggestions. A sparkle
“Suggest settings” action reapplies them. Ordinary reruns, additional methods
and review/back preserve manual edits. New data invalidate the old configuration
and approval. EPDE retains explicit Default, Quick, Thorough and Custom budgets.
Heavy registry records remain metadata-only in the website.

Suggestions start from existing scientific profiles, use geometry, declared
added noise and existing resource limits, and explain their basis. A small
versioned historical index reports compatible prior execution experience.
The available archive is not a hyperparameter sweep; no learned optimality claim
or truth-based choice of parameters is made. No training occurs on suggestion.

Compare highlights measurable leaders with their scope and limitations. Missing
scores remain missing. Method objectives, oracle best-front recovery, selected
equation quality, reconstruction, held-out accuracy and runtime have distinct
meanings. Only compatible observations support a comparison. Each run receives
evidence-based suggestions for further checking or improvement.

## Boundaries

Existing method validators, queue transport, hosted execution limits, ownership,
input identities and portable scientific manifests remain authoritative. No new
dependency, private-session evidence scan, heavy dataset loading or remote model
service is needed. The user authorized implementation and GitHub integration.
